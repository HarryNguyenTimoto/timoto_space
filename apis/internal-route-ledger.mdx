# Internal OPS API Route Ledger

## Webhooks and operator offer

- POST /api/webhooks/tma/new-submission/ -> TmaNewSubmissionWebhookView
- POST /api/webhooks/bank/payout/ -> BankPayoutWebhookView
- POST /api/v1/mobile/operator-offer/ and no-slash alias -> MobileOperatorOfferReadView

The TMA and bank paths are integration endpoints, not ordinary staff UI calls. Signature, event identity, replay behavior and allowed body must come from handler. Operator-offer may use a separate mobile secret/signature validation; do not conflate the two HMAC schemes.

- POST /api/submissions/:bike_id/ai-review-choice/
- GET /api/submissions/:bike_id/ai-report/
- POST /api/submissions/:bike_id/submit/
- POST /api/submissions/:bike_id/reject/
- GET /api/submissions/:bike_id/success/

Handlers are in submissions_api.py. Queue and detail are read projections. Submit/reject are mutating commands. Success is a projection and should not be treated as a command. AI choice/report are separate: selected recommendation does not itself equal confirmed valuation.

## Vehicle sale routes

- GET /api/vehicles/
- GET /api/vehicles/pending-sale/
- GET /api/vehicles/:bike_id/
- POST /api/vehicles/:bike_id/sale/
- POST /api/vehicles/:bike_id/sale/complete/
- POST /api/vehicles/:bike_id/sale/fail/

sales_api.py calls domain helpers in sale.py. Complete and fail have transition requirements. Sale completion can publish eligible gas vehicles into dealer catalog according to configuration. Capture transaction boundary and publication retry behavior before promising atomic cross-database completion.

## Response body evidence

Responses are custom APIView payloads, not guaranteed common DRF serializer envelopes. Inspect \_sale_error_response in sales_api.py/purchases_api.py and response builders in api_helpers.py, purchases_api.py, and submissions_api.py. Business transition exceptions are converted to an API error body. Record status and body for each exception branch and preserve current status codes; don't standardize without API versioning.

Authentication is centralized in permission helpers such as \_require_ops for purchases. For each view, publish anonymous result, authenticated wrong-role result, not-found result, invalid-state result and success fixture. A route's presence in api_urls.py alone does not say whether it is public or role protected.

## Mismatches corrected from prior page

The actual valuation pricing route is /api/valuation/bikes/:bike_id/pricing/, not /api/valuation/pricing/. Purchase commands use inspection/pass, deposit/pay, notary/confirm segments. Internal APIs name bike UUID in purchase paths even though user interface calls them purchases. Mobile callback routes under /api/webhooks/\* are distinct from internal dashboard calls. Use these exact route strings for Postman sync.
