Route defect: two view functions are registered at /auth/me/ for GET profile and PUT/PATCH update. Django resolves the first matching path before the view handles the HTTP method, so the earlier GET-only function is likely to shadow the later update function and return 405 for PUT/PATCH. Confirm with Django URL resolver/API test and merge the methods into one view or use a distinct route.

- /auth/logout/
- /user/profile and /user/change-password
- /options/wards
- /marketplace/purchase-orders/\* and /marketplace/payments/\*
- /marketplace/listings/... paths differ in base shape from backend only if other service version is used. Every mismatch needs its own row: caller file, configured base URL, expected service, matching Django resolver, live smoke result, owner. A not-found URL may be owned by another target; do not patch this backend until the base URL is established.
