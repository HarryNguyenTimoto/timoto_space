# timoto-mobile Complete API Technical Specification

This document provides a line-by-line, zero-handwaving API reference for the **timoto-mobile** backend service (`api.timoto.ai`).

---

## 1. Authentication & Identity Subsystem (`/api/v1/auth/`)

### 1.1 POST `/api/v1/auth/mobile/signup/`

- **File Location**: `backend/apps/users/views.py` (`mobile_signup`)
- **Authentication**: `AllowAny`
- **Headers**: `Content-Type: application/json`
- **Request Body**:

```json
{
  "phone_number": "0987654321"
}
```

- **Validation**: Regex `^(0|\+84)[3|5|7|8|9][0-9]{8}$`.
- **Database Side Effects**:
  - Checks `CustomUser` table. If exists, returns 400.
  - Upserts `PendingUser` record with `phone_number` and temporary hashed secret `TempPassword123!`.
- **201 Created Response**:

```json
{
  "status": "ok",
  "message": "Pending user created. Proceed to send OTP."
}
```

- **400 Bad Request Response**:

```json
{
  "status": "error",
  "error": "PHONE_EXISTS",
  "message": "Số điện thoại này đã được đăng ký tài khoản."
}
```

### 1.2 POST `/api/v1/auth/mobile/send-otp/`

- **File Location**: `backend/apps/users/views.py` (`mobile_send_otp`)
- **Authentication**: `AllowAny`
- **Request Body**:

```json
{
  "phone_number": "0987654321"
}
```

- **Execution & AWS Integration**:
  - Invokes AWS SNS `Publish` API in `ap-southeast-1` to dispatch 6-digit OTP SMS code.
  - Updates `PendingUser.confirmation_code` and `PendingUser.code_created_at`.
- **200 OK Response**:

```json
{
  "status": "ok",
  "message": "OTP code sent via SMS."
}
```

### 1.3 POST `/api/v1/auth/mobile/verify-otp/`

- **File Location**: `backend/apps/users/views.py` (`mobile_verify_otp`)
- **Authentication**: `AllowAny`
- **Request Body**:

```json
{
  "phone_number": "0987654321",
  "code": "123456"
}
```

- **Verification Logic**:
  - Matches `code` against `PendingUser.confirmation_code` or `DEV_OTP_PASSWORD`.
  - On match, calls Cognito `AdminCreateUser` & `AdminSetUserPassword`.
  - Creates permanent `CustomUser` row in PostgreSQL.
  - Deletes `PendingUser` row.
  - Calls Cognito `AdminInitiateAuth` (`ADMIN_NO_SRP_AUTH`) to issue JWT tokens.
- **200 OK Response**:

```json
{
  "status": "ok",
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "id_token": "eyJhbGciOi...",
  "user": {
    "id": "a8f3b290-7d12-4c56-8e99-1a2b3c4d5e6f",
    "phone_number": "0987654321",
    "role": "RIDER"
  }
}
```

- **400 Invalid Code**:

```json
{
  "status": "error",
  "error": "INVALID_OTP",
  "message": "Mã OTP không chính xác hoặc đã hết hạn."
}
```

### 1.4 POST `/api/v1/auth/mobile/login/` & `/api/v1/auth/mobile/verify-login-otp/`

- **File Location**: `backend/apps/users/views.py`
- **Authentication**: `AllowAny`
- **Step 1 Request (`login/`)**: `{"phone_number": "0987654321"}` -\> Triggers SNS OTP to existing user.
- **Step 2 Request (`verify-login-otp/`)**: `{"phone_number": "0987654321", "code": "123456"}` -\> Returns Cognito JWT tokens.

### 1.5 Social Auth: POST `/api/v1/auth/zalo/native/` & `/api/v1/auth/apple/native/`

- **Zalo Native Payload**: `{"zalo_id": "string", "access_token": "string"}` -\> Validates with Zalo Graph API proxy, authenticates in Cognito via HMAC synthetic password `zalo_<id>_<secret>`.
- **Apple Native Payload**: `{"identity_token": "string", "user_id": "string"}` -\> Validates Apple JWT signature, extracts email/sub, provisions Cognito rider.

## 2. Options & Catalog Reference Subsystem (`/api/v1/options/`)

### 2.1 GET `/api/v1/options/brands` & `/models` & `/years`

- **File Location**: `backend/apps/options/views.py`
- **Authentication**: `AllowAny`
- **Query Params for `/models`**: `?brand=Honda`
- **200 OK Response (`/brands`)**:

```json
{
  "status": "ok",
  "data": ["Honda", "Yamaha", "Piaggio", "SYM", "Suzuki", "VinFast"]
}
```

### 2.2 GET `/api/v1/options/price-range`

- **File Location**: `backend/apps/options/views.py` (`get_motorcycle_price_range`)
- **Query Params**: `?brand=Honda&model=SH 150i&year=2020`
- **Calculation Logic**: Queries `options_fairmarketprice` table. Computes `min_price = FMP * 0.7`, `max_price = FMP * 1.1`, rounded to 100,000 VND.
- **200 OK Response**:

```json
{
  "status": "ok",
  "price_range": {
    "min_price": 65000000,
    "max_price": 88000000,
    "suggested_price": 78000000,
    "price_source": "fmp"
  }
}
```

## 3. Bike Management & Seller Flow (`/api/v1/bikes/`)

### 3.1 POST `/api/v1/bikes/` (Create Bike Draft)

- **File Location**: `backend/apps/bikes/views.py` (`BikeViewSet.create`)
- **Authentication**: `IsAuthenticated` (Bearer Token)
- **Request Body**:

```json
{
  "device_id": "device_12345",
  "brand": "Honda",
  "model": "SH 150i",
  "year": 2021,
  "license_plate": "59P1-12345",
  "mileage": 15000,
  "expected_price": 75000000,
  "city": "TP.HCM"
}
```

- **201 Created Response**:

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "status": "DRAFT",
  "brand": "Honda",
  "model": "SH 150i",
  "year": 2021,
  "created_at": "2026-08-21T10:15:30Z"
}
```

### 3.2 POST `/api/v1/bikes/{bike_id}/evaluate/async/`

- **File Location**: `backend/apps/bikes/views.py` (`evaluate_async`)
- **Authentication**: `IsAuthenticated`
- **Database Side Effects**:
  - Updates `bikes_bike.status = 'EVALUATION_PENDING'`.
  - Dispatches async task to AI evaluation engine.
  - Sends HMAC Webhook POST to `timoto-internal-app` (`/api/webhooks/tma/new-submission/`).
- **202 Accepted Response**:

```json
{
  "status": "ok",
  "message": "Evaluation started asynchronously.",
  "bike_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6"
}
```

### 3.3 POST `/api/v1/bikes/pickup-schedule/` & TMA-168 Reschedule

- **File Location**: `backend/apps/bikes/views.py` (`create_pickup_schedule`)
- **Authentication**: `IsAuthenticated`
- **Request Body**:

```json
{
  "bike_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "scheduled_date": "2026-08-25",
  "scheduled_time_slot": "09:00 - 11:00",
  "address": "123 Nguyen Hue, Quan 1, TP.HCM",
  "contact_name": "Nguyen Van A",
  "contact_phone": "0987654321"
}
```

- **Database Side Effects**:
  - Executes Raw SQL `INSERT INTO bikes_pickupschedule`.
  - Triggers `pg_notify('pickup_scheduled', ...)` postgres notification.
- **TMA-168 Reschedule Flow**:
  1. `PATCH /api/v1/bikes/pickup-schedule/{id}/` with `{"status": "CANCELLED"}`.
  2. `POST /api/v1/bikes/pickup-schedule/` with new date/slot.

## 4. Dual-Price & Seller Listing Subsystem (TMA-79) (`/api/v1/evaluation/`)

### 4.1 POST `/api/v1/evaluation/price-selection/{bike_id}/`

- **File Location**: `backend/apps/evaluation/views.py` (`seller_price_selection`)
- **Request Body**:

```json
{
  "selected_option": "LISTING",
  "desired_price": 78000000
}
```

- **Options**: `"LISTING"` (Higher market listing price) vs `"INSTANT"` (Immediate cash payout).

### 4.2 POST `/api/v1/evaluation/listing/{bike_id}/confirm/`

- **File Location**: `backend/apps/evaluation/views.py` (`confirm_seller_listing`)
- **Database Side Effects**: Sets `marketplace_status = 'LISTED'`, makes bike visible in buyer Marketplace catalog.
