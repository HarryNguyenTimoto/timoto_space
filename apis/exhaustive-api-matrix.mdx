# API and integration contract matrix

This page is the navigational contract for the seven-project TiMoto system. It names route families and cross-project handoffs present in source. It deliberately does not fabricate a single payload schema where a serializer, raw SQL handler, webhook, or client expectation is the actual authority.

For request/response examples and line-level behavior, use the linked deep references. For ownership, state machines, and deployment boundaries, read the [Seven-project specification](/architecture/seven-project-spec).

| Rider API | api-staging.timoto.ai | api.timoto.ai | Cognito/JWT for rider routes; selected auth/OCR/options paths are public | WebSocket/realtime uses a rider token on the connection path. Confirm deployed route prefixes before testing. |

| Chotot data | Lambda/EC2 jobs | Lambda/EC2 jobs | AWS task/runtime credentials | Chotot gateway calls are not product API calls and do not write Aurora. |
| Repair control plane | AWS control plane | AWS control plane | IAM task roles, Cognito/API Gateway read scope, signed artifacts | It observes registered targets and may create draft PRs; it does not merge/deploy. |

## Dealer browser — timoto_dealer_portal_v2

This repository is a Vite/React SPA, not a Django service and not a second API owner.

- Build scripts are build, build:staging, and build:production; configuration is injected through VITE\_\* values.
- Axios wrappers live under frontend/src/api/; route declarations and wrapper methods are client expectations, not proof that the backend route is mounted.
- Auth uses stored tokens and an interceptor. The source distinguishes the token used for login detection from the token attached to API requests; check request flags when a user looks logged in but receives 401.
- The SPA includes auth, catalog/bike, order, payment, AI-report and Zalo callback screens. Client reminder timers in local storage are not the server notification inbox.
- nginx serves the static bundle and SPA fallback. Deployment evidence must include the built image, API base, nginx config and matching dealer backend host.

Detailed behavior is covered by [v1/v2 split](/dealer-portal/migration-v1-to-v2) and [SPA user cache/reminders](/dealer-portal/spa-user-cache-reminders).

## Public landing — TiMoto-AI-Web

Detailed references: [Landing static deploy](/ai-web/landing-static-deploy) and [waitlist Lambda](/ai-web/waitlist-lambda).

- The checked-in frontend is Vite + React 18 with only / and /landingpage routes.
- It contains marketing copy, app-store links and an Android waitlist modal.
- submitAndroidWaitlist currently validates that phone or email is present, shows a browser alert, clears local state, and closes the modal. It does not call API Gateway, Lambda, DynamoDB, or a dealer/mobile evaluation API.
- The separately documented waitlist Lambda accepts phone/email, normalizes Vietnam phone values, queries phone/email GSIs, and returns 201 for a new item or 200 for a duplicate. Query-then-Put is not a strong uniqueness guarantee.
- Do not describe this repository as the AI valuation engine. The valuation path is mobile plus the separate gRPC service.

## Market-data pipeline — chototcaodulieu

Detailed references: [pipeline constants](/scraper/chotot-pipeline-constants), [parsing and deduplication](/scraper/parsing-deduplication), and [image sync](/scraper/image-sync-s3).

- Listing API: Chotot v1 listing endpoint with motorcycle category cg=2020, page size 50 and bounded retries.
- Detail API: v2 listing detail fetch with a bounded worker pool. Missing detail is recorded as a miss and not treated as a valid bike.
- Daily path: scrape yesterday in Vietnam time, upsert raw records to DynamoDB chotot-xe-may, and optionally write UTF-8-BOM CSV to S3.
- Weekly path: scan only list_id, refresh details in bounded batches, persist a checkpoint, and asynchronously self-invoke when the 780-second budget is reached.
- Quality export requires active/accepted status, price range, title length, image, region, seller and list time. It emits a raw per-bike report, not an Aurora import.
- Current source uses standard headers and retry/backoff. There is no verified proxy list, residential proxy pool or proxy-rotation implementation in the reviewed code.
- Image-sync producer/worker turns DynamoDB records into SQS jobs, downloads source URLs, writes the dashboard bucket and tracks state.

## Incident-repair control plane — AI_infra_timoto

Detailed reference: [AI Repair Foundation](/architecture/timoto-ai-repair-foundation).

The registered target identity is derived from timoto_repair/registry.py, not from an incident payload. Intake normalizes accepted 5xx event shapes, deduplicates event IDs, and groups route evidence conservatively. The source broker obtains a full release SHA and bounded backend snapshot; the repair/model runner receives no GitHub credential. Independent tests and verifier receipts are required before a signed artifact and draft PR. The publisher can create a draft PR only; merge, deployment, rollback and production data changes remain human-controlled.

## Contract hygiene rules

1. Use the route and serializer in the owning repository as the API authority; treat client wrappers and old Postman collections as expectations until tested.
2. For every cross-project write, record source ID, destination ID, auth proof, idempotency key, response, and durable state change.
3. Keep staging and production host, region, task definition, image digest and database alias explicit.
4. Never place customer media, raw tokens, HMAC secrets or unbounded logs into model context, PR bodies, Jira descriptions or browser payloads.
5. A passing local suite, HTTP 200, running ECS task, Jira key or PR URL is evidence of one step only—not proof of end-to-end business correctness.
