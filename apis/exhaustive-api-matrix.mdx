## Shared integration edges

| Source | Destination | Transport/data | Durable truth |
| --- | --- | --- | --- |
| Rider app | Mobile Django | JWT/auth + JSON/multipart | Django bike/evaluation/media rows |
| Mobile Django | Internal OPS | HMAC webhook or mirrored DB/outbox | Receiver row plus sender event/outbox status |
| Internal OPS | Mobile Django | signed operator offer/completion event | pricing decision and mobile result record |
| Internal OPS | Dealer catalog | conditional publish/sync | dealer combo/catalog row |
| Dealer backend | VietQR/VNPay | checkout intent and signed callback/IPN | local checkout/payment after verified callback |
| Chotot collector | DynamoDB/S3/SQS | scheduled HTTP ingestion and object jobs | listing ID, refresh checkpoint and image state |
| Backend observability | AI repair control plane | trusted CloudWatch binding and sanitized 5xx event | incident state bound to target and release SHA |
| AI control plane | GitHub | verified artifact, repair branch, draft PR | signed artifact plus durable publication receipt |

These edges use different databases and authentication schemes. Do not infer one universal API prefix, user ID, error envelope or transaction boundary.

## Contract status labels

- Declared: route appears in a backend URL module.
- Called: frontend has a method/path call.
- Matched: client path resolves to the intended backend handler.
- Tested: a test asserts status/body/side effect.
- Environment verified: same environment was reached with current credentials.
- Proposed: new standard or behavior, not current source behavior.

Only say an endpoint is live when the last status is supported by fresh environment evidence. API references include client/backend mismatches and known path drift.

## Response classification

Use /apis/response-contracts-evidence for success/error semantics. There is no proven shared envelope across the seven roots. Each endpoint page needs its own success status/body/content type, error body, auth, side effect, retry/idempotency and test evidence. Browser redirect, QR display, websocket notification, and UI alert do not establish final payment, evaluation, or waitlist state.

## Current highest-risk contract gaps

1. Mobile client marketplace purchase/order/payment paths are not declared in the inspected mobile Django URL modules; identify their actual owner.
2. Mobile /auth/me/ GET and update functions are declared as two same-path URL entries; resolver ordering likely shadows the later update handler and should be tested.
3. Dealer has modern /api/v1 routes and legacy /api aliases; verify both against the same permissions and payment semantics.
4. VietQR/VNPay callback settlement must be idempotent and amount/signature bound; browser return is not settlement.
5. Internal OPS write/outbox delivery are separate durability events.
6. AI repair publication stops at draft PR; human approval owns merge/deploy.
7. AI Web waitlist/email forms currently show local feedback without server persistence.
8. Chotot advertisements are external market data, not transaction inventory.

## Change procedure

When an API changes, update backend route, view/schema, frontend caller/type, route ledger, response example, error fixture and integration test together. Record repository commit and environment. For a cross-repo call, record caller, base URL, target service, credential, idempotency and reconciliation owner.
