## Cross-system flow map

1. Rider creates bike, uploads media, submits evaluation and sees async result.
2. Seller opens operator review; OPS prices with snapshot rates, emits an outbox event and mobile reads the persisted result.
3. Seller chooses listing/instant path; marketplace read model derives eligibility and presentation.
4. Pickup, sale and purchase states are separate transitions. A notification is not a state transition.
5. Dealer chooses grouped Combo or auction item, creates checkout, receives QR instructions, then provider callback settles payment.
6. Chotot scraper stores external market advertisements and exports; these records are not TiMoto transaction inventory.
7. Backend 5xx evidence enters AI control plane, gets bound to target and commit, verified, signed and published as draft PR. Human controls merge and deployment.

## Evidence labels

- Code route: declared by URL resolver.
- Client route: called or typed by frontend; backend implementation must be located.
- Source behavior: handler/serializer/model behavior found in repository.
- Environment verified: same target/environment request or deployment evidence observed.
- Proposal: future contract or safety improvement, not current implementation.

Every endpoint row should carry its evidence label. A code route does not prove deployment; a client type does not prove server support; a 2xx response does not prove the intended durable state.
