## Catalog, bikes, orders, auctions

Catalog router has authenticated and public routers for bikes, with filter-options routes. Exact viewset actions:

- /api/v1/catalog/bikes/ collection/detail
- /api/v1/catalog/public/bikes/ collection/detail
- /api/v1/catalog/filter-options/
- /api/v1/catalog/public/filter-options/

The mount includes legacy /api/catalog/. Public viewsets must use a restricted serializer. Catalog Combo groups multiple physical Bike UUIDs.

Bike assessment router: /api/v1/bikes/ and detail/action routes from BikeAssessmentViewSet. Evaluation: GET /api/v1/evaluations/bikes/:bike_id/ai-report/. Notification router registers /api/v1/notifications/ and /api/v1/notification-devices/ (ViewSet actions may add detail routes).

Orders router is registered at empty path under /api/v1/orders/ and legacy /api/orders/. Inspect DealerOrderViewSet actions for methods beyond CRUD and confirm permission scoping. Auction router registers /api/v1/auctions/.

## Checkout/payment state boundaries

Create-deposit/full-payment creates an intent/reference. QR generation creates payment instructions. Browser return displays provider redirect state. IPN/VietQR callback is the trusted settlement input after signature verification and local reference/amount validation. Confirmation page/PDF reads a durable state. Status and delivery read paths are projections. A paid flag should only follow validated provider evidence and one transaction that settles the local checkout/order idempotently.

Callback implementation must be read in backend/payments/views.py and checkout_views.py. Capture:

- provider auth/signature fields;
- local lookup key;
- amount/currency comparison;
- duplicate transaction response;
- unknown order response;
- transaction locking and commit point;
- outbound acknowledgement format. No generic “2xx means paid” client interpretation is safe.

## Legacy route migration

Track callers separately for /api/v1/ and /api/. Compatibility routes can have subtly different payment semantics and session expectations. Deprecation needs access logs by route, caller mapping, announced sunset, and a period with tests. Do not remove route aliases because new clients use v1.

## Contract testing

- Resolve every method/path with Django URL resolver in a configured test process.
- Assert unauthenticated, authenticated wrong dealer, and correct dealer response.
- Test Combo ownership and private-field suppression.
- Test checkout create retry, QR refresh, callback duplicate, amount mismatch, wrong merchant, signature mismatch, unknown checkout and callback race.
- Verify redirects do not mutate paid state.
- Verify PDF content type, filename and authorization.
- Verify router-generated detail/action methods rather than inferring from URL shape.
