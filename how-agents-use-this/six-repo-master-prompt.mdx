## Summary

This is the **master prompt** for any agent session whose job is to read all six TiMoto repos, understand the full product, **visualize** it, and **update the private Mintlify KB** (`timoto-ai`). Copy the block below into Cursor / Claude Code as the first message.

Companion pages: [Deep prompt (per-hop contracts)](/how-agents-use-this/deep-prompt) · [How agents use this](/how-agents-use-this) · [Getting started](/index).

**Do not** ask for 10k–20k lines of filler. **Do** require every screen hop and every money-path API to have request \+ 200 JSON \+ DB \+ FE bind.

═══════════════════════════════════════════════════════════════
PHASE 4 — HOP BLOCK (REQUIRED FOR EVERY API CALL IN A FLOW)
═══════════════════════════════════════════════════════════════

### Hop: <Screen or job> → <METHOD /path>

- **Why** (one sentence from spec or product rule)
- **Caller:** `<file>:<function or component>`
- **Auth:** JWT Bearer | OPS JWT | HMAC | AllowAny
- **Request:** full JSON (or query params)
- **200/201:** full JSON from Postman example or Django test — **never invent fields**
- **Other statuses:** 401, 404, 409, 422 — what FE shows (toast, alert copy from spec)
- **DB write:** `table.column` (e.g. `pricing_entries.offer_to_user`, `bikes.marketplace_status`)
- **DB read:** who consumes next (HMAC offer, sale-history card, OPS submissions list)
- **FE bind:** widget label (VI) → JSON key (e.g. Đăng bán → `listing_price_vnd`)
- **SPEC GAP:** if spec shows a field UI does not render (OPS Listing/TIPP preview)
- **Next screen** on success / on failure

Locked product facts (do not get wrong):
- FMP = `offer_to_user` only from OPS; listing = FMP×0.95×0.90; TIPP = FMP×0.75; snapshot on OPS submit.
- TMA-168: PATCH pickup `status: cancelled` ≠ POST sale-history cancel.
- Evaluate in Apps = `POST .../evaluate/async/` + poll; **not** `/evaluation/full/`.
- HMAC operator-offer is server-to-server only.
