## Executive summary

This workspace is the TiMoto AI incident-repair control plane. It is not the complete Dealer, Internal, or Mobile application source. Those application repositories are external targets referenced by the registry and source broker.

The intended lifecycle is:

**backend 5xx event → exact target resolution → sanitized CloudWatch evidence → SQS and durable incident record → immutable source snapshot → isolated model and test stages → independently verified candidate → signed artifact → GitHub draft PR → Jira and read-only operations console → human approval → operator-controlled deployment and observation**

The design is deliberately approval-gated. A draft PR is not a merge, a merge is not a deployment, and a running ECS task is not proof that an API is healthy.

## Folder 2 — infra/

infra/ is the main Terraform stack for the repair pipeline.

### Intake and evidence

main.tf defines:

- A Bangkok provider alias for source log groups.
- A Singapore SQS evidence queue and encrypted DLQ.
- A PAY_PER_REQUEST, encrypted, point-in-time-recoverable DynamoDB incident table.
- An existing private S3 evidence bucket, written only under controlled prefixes.
- Forwarder and collector Lambda functions.
- Per-target CloudWatch subscription filters, enabled only for validated target IDs.
- A DLQ-visible alarm.

The forwarder accepts only structured API exception or API request 5xx events. It validates CloudWatch ownership, log group, stream prefix, ECS task identity, cluster, service group, and primary container before queuing normalized evidence.

### Dispatch and source handoff

dispatcher.tf and source-handoff.tf provide:

- Durable two-slot reservations.
- Per-repository exclusion.
- Frozen ECS RunTask requests and deterministic client tokens.
- Deadline supervision and ambiguous-launch reconciliation.
- A separate source-broker launch before model execution.
- A source-handoff Lambda that promotes one immutable, target-bound snapshot.

Capacity is not released solely because a lease expired. A missing ECS task record remains a reconciliation case.

### Runners and verification

runner.tf and model-runner.tf provision:

- Digest-pinned ARM64 preview, model, and test-runtime task definitions.
- Separate execution/task IAM roles.
- A KMS asymmetric signing key.
- S3 prefixes for snapshots, candidates, results, tests, and artifacts.
- Secrets Manager access only where the specific task needs it.

The verifier is the authority that validates the candidate and signs the artifact. The model task writes an unsigned candidate and cannot create a PR.

### Publisher, Jira, and observability

- github.tf defines source-broker and GitHub-publisher images, roles, logs, and task definitions.
- jira.tf defines the scheduled Jira synchronizer.
- observability.tf defines metric filters, alarms, and the repair dashboard.
- test-runtimes.tf declares immutable ECR repositories for Dealer, Internal, and Mobile test images.

Current Terraform source configures supervised draft-PR dispatch for staging and production. It does not grant merge or deployment authority to the model or publisher. Production merge/deploy remains a human boundary and must be verified against live configuration before any operational change.

### State and release hygiene

The folder contains Terraform state, backup state, saved plans, and generated ZIP artifacts. These are operational artifacts, not ordinary source files. The workspace is not currently a Git repository, so there is no commit history or clean/dirty status to rely on here.

## Folder 3 — platform/

platform/ is a read-only operations console, separate from the repair workers.

### Backend

platform/backend/app.py:

- Reads incident rows, evidence summaries, receipts, test results, and ECS service observations.
- Redacts sensitive strings and returns bounded projections.
- Generates deterministic three-hour reports.
- Exposes identity triggers for Cognito signup/token checks.
- Never returns raw request bodies, raw logs, model prompts, patches, or credentials.
- Does not mutate incidents, launch tasks, merge PRs, or deploy services.

The authenticated API surface is:

- GET /overview
- GET /incidents/{id}
- GET /reports
- GET /reports/{id}

### Infrastructure and frontend

platform/infra/main.tf provisions:

- Private S3 static assets behind CloudFront.
- Cognito email/password authentication restricted to the company domain.
- Optional TOTP configuration.
- API Gateway HTTP API with JWT authorizer and console/read scope.
- Three small ARM64 Lambdas: API, report generation, and identity triggers.
- A three-hour EventBridge report schedule.
- Versioned report storage with bounded retention.

platform/web/ is a dependency-free SPA. It displays overview, incidents, reports, runbook guidance, and explicit limitations. It is intentionally an observation console, not a repair control surface.

## Folder 4 — services/

The services folder contains isolated execution roles. Each container has a narrower authority than the full pipeline.

### Source broker

services/source-broker/broker.py owns the GitHub read credential. It:

1. Requires a full 40-character release SHA.
2. Reads only the target repository’s backend/ tree.
3. Applies file, count, size, and archive budgets.
4. Writes a SHA-bound archive and manifest to private S3.
5. Emits a bounded blocked receipt on failure.

The source broker never passes its GitHub credential to the model or test task.

### Preview repair runner

services/repair-runner/runner.py is deliberately preview-only. It validates the incident, lease, evidence, source manifest, and archive metadata, then writes a blocked receipt. It does not clone, invoke a model, call GitHub/Jira, mutate DynamoDB, or deploy.

### Model runner

services/model-runner/model_runner.py:

- Restores operator-provisioned Antigravity state through the bootstrap boundary.
- Reads immutable source and sanitized evidence.
- Applies an operator-reviewed per-target test contract.
- Invokes the configured model only inside the guarded task.
- Restricts model changes to backend Python files.
- Sends source and candidate archives to the independent test task.
- Requires a real baseline failure and candidate pass.
- Writes an unsigned candidate payload or a blocked receipt.

The synthetic drill fallback is marked separately as repair_origin=drill_fallback; it must not be presented as proof of a new autonomous diagnosis.

### Test runner

services/test-runner/test_runner.py is an untrusted-code task with no Secrets Manager, KMS, DynamoDB, GitHub, Jira, or model credentials. It:

- Downloads immutable source and candidate archives.
- Rejects unsafe archive members and traversal.
- Runs the approved command on both source and candidate.
- Executes the selected regression explicitly.
- Distinguishes setup/import failures from assertion failures.
- Writes a bounded test receipt to S3.

### Publisher and OAuth bootstrap

- services/github-publisher/publisher.py is the signed-artifact to GitHub draft-PR boundary. It does not merge, dispatch workflows, or deploy.
- services/oauth-bootstrap/login.py is an operator-only ECS Exec persistence helper. It is restricted to authentication and usage verification, not coding prompts.
- entrypoint.sh files restore state and start the bounded runtime process.

## Folder 7 — tools/

The tools are operator-facing and should not be called by the model as an authority.

- six_target_smoke.py performs read-only repository shape, ECS steady-state, HTTPS reachability, and test-contract preflight checks.
- demo_fast_e2e.py creates one synthetic staging incident, shortcuts scheduled waits, and exercises source handoff, model/test stages, verifier, publisher, and Jira. It is a staging drill, not production repair evidence.
- staging_deploy.py requires a short-lived approval file, staging target, expected current task definition, new task definition, and HTTPS health check. It attempts rollback if the deployment or health gate fails.

The tools preserve an important operational distinction: a health URL returning 200 does not prove the deployed release matches the approved artifact or that the original error disappeared.

## State and trust boundaries

A normal incident moves through these conceptual states:

QUEUED → READY / LAUNCHING / RUNNING → RESULT_PENDING → BLOCKED or ARTIFACT_READY → PR_PENDING → AWAITING_APPROVAL → DEPLOYING → VERIFYING → RESOLVED or ROLLBACK_REQUIRED

Not every state is a success claim:

- QUEUED: evidence accepted; no repair claimed.
- RUNNING: a bounded task exists; no result accepted.
- RESULT_PENDING: worker stopped or receipt is awaiting reconciliation.
- BLOCKED: a required gate failed or evidence was insufficient.
- ARTIFACT_READY: candidate passed the verifier’s artifact/test contract.
- AWAITING_APPROVAL: a draft PR exists and awaits human review.
- RESOLVED: deployment observation met the configured evidence window.
- ROLLBACK_REQUIRED: observation detected drift or matching failures.

## Source-of-truth rules

When documents, local configuration, and live infrastructure disagree:

1. Treat the exact deployed task definition/image digest and authenticated AWS read as runtime truth.
2. Treat the immutable source SHA and artifact manifest as repair provenance.
3. Treat Terraform plans as intended changes, not proof of application.
4. Treat Jira/PR links as recorded integrations, not proof of current external status.
5. Keep implemented, tested, committed, pushed, deployed, live, and blocked separate.
